Troubleshooting and Optimization Report

Project Goal
This portfolio project demonstrates how a Python-based RPA-style flight-booking workflow can be debugged and redesigned for reliability, observability, and maintainability.

Implemented Improvements
- Deterministic sample-data generation using a configurable random seed.
- Validation for required fields, PNR format, airport codes, booking status, fares, and route integrity.
- Duplicate handling based on PNR.
- Separation of validation, workflow processing, retry behavior, and metrics into testable functions.
- Structured logging for invalid records, skipped bookings, retry events, and failed confirmations.
- Bounded retry logic with exponential backoff for simulated transient service failures.
- Unit tests covering reproducibility, validation, deduplication, and pipeline summary behavior.
- Clear run instructions and repository documentation.

Data Model
Each reservation contains:
- PNR: six-character uppercase alphanumeric booking reference
- Passenger: traveler name
- Origin: supported IATA airport code
- Destination: supported IATA airport code
- Fare: positive numeric value
- Status: Confirmed, Checked-in, Pending, or Canceled

Validation Rules
1. All required fields must exist.
2. PNR must match [A-Z0-9]{6}.
3. Passenger cannot be blank.
4. Origin and destination must be in the supported airport set.
5. Origin and destination cannot be the same.
6. Fare must be numeric and greater than zero.
7. Status must be one of the supported booking statuses.

Failure Handling
Validation failures are treated as permanent input errors and are not retried.
Transient downstream confirmation failures are retried up to a configured maximum attempt count.
Each retry is logged and uses exponential backoff.

Workflow Metrics
The pipeline returns:
- input_records
- valid_records
- processed
- skipped
- failed
- retries

These metrics are generated from each execution rather than hard-coded.

Optimization Notes
The original notebook demonstrated synthetic reservation generation but did not implement the debugging and optimization behaviors described in the earlier report. The improved repository now contains executable source code and tests so the documented behavior can be verified.

The design favors correctness and clarity over artificial benchmark claims. Performance numbers should only be added when they are measured from a reproducible benchmark on a documented environment.

Testing
Run:
python -m unittest discover -s tests

The tests verify:
- deterministic data generation
- valid route generation
- fare normalization
- missing-field rejection
- invalid-airport rejection
- duplicate PNR handling
- pipeline summary counts

Portfolio Positioning
This project demonstrates practical skills relevant to automation engineering, Python development, technical support automation, and operations tooling:
Python, RPA, debugging, exception handling, data validation, structured logging, retry logic, workflow design, unit testing, and maintainability.

Limitations
This is a simulated portfolio workflow. It does not connect to a live airline reservation system, payment processor, or production confirmation API.
